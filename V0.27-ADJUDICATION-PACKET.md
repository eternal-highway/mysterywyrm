evidence, fixes its identity, orders the tests, and states what an answer must
contain. Every reading in this repository stands exactly as it stood at

## 2. Evidence identity rules

These rules exist because the evidence pool contains near-neighbours that can
be confused for one another, one of which would silently corrupt the key test.

1. **Identify every carrier by post, local archive filename, canonical source
   URL, and SHA-256 together.** Never by dimensions alone. The archive filename
   may carry the harvester's `YYYY_MM_` prefix; the source URL basename does not.
2. **Never select an asset because it is the largest.** For *Loop*, the
   filename-run asset `2023_03_253-E-Letters-for-Titles-Vern-Tonkin.jpg`
   (1614×2521) is taller than the key plate
   `2021_11_Loop.lettersfortitles-verntonkin.jpg` (2062×1528). A
   largest-dimension rule selects the wrong file and the key test silently reads
   a plate that is not the key.
3. **Join on normalized canonical media URL, never on slug.**
   `CROSS-LINEAGE-FINDINGS.md` § 3c records that the two lineages use different
   slug conventions. A slug join of the register against `data/media-code.json`
   drops *Everything is Temporary* (seed `everything-is-temporary`, harvest
   `everything-temporary`) without error. Compare exact URLs first. Where both
   values are WordPress upload-media URLs, normalize only a terminal WordPress
   derivative suffix immediately before the extension: strip `-<width>x<height>`
   and `-scaled`; do not rewrite the directory or any other basename text. Raw
   URL equality matches fourteen registered carriers. This normalization also
   matches *Loop* (`-1080x800` versus the original) and *Œ is for Œdipean
   Riddle* (`-1080x1080` versus `-scaled`), yielding sixteen of seventeen.
   The only residual failure is *Octave*, whose seed row holds a page URL rather
   than an image URL — the registration gap itself, not a join defect. Do not
   normalize page URLs into media identities.
4. **A downscaled derivative never rules over a larger original.** Where the
   seed's cited source and the harvest's manifest disagree in size, the larger
   bytes are the evidence.
5. **Record which bytes were actually read**, by SHA-256, in every output.

## 4. Gate 0 — re-derive the *Loop* key before any plate is read

*Loop* is not a message. `research/rune-code.md` records it as the worked table
of all 29 runes, and both lineages classify it as key rather than plaintext.
Every coordinate on every other plate is interpreted through that table.
`CROSS-LINEAGE-FINDINGS.md` § 2 records that the seed read it at **1080 × 800**
when **2062 × 1528** exists.

So the key is tested first, and nothing else is read until it resolves. *Loop*
appears in § 3 among the seven agreeing carriers because its **transcription**
is not disputed; it is nonetheless the first test here, because agreement at
1080 × 800 is not evidence of agreement at full resolution.

### 4.1 Acquire and authenticate the bytes

The full-resolution images are **not in the repository**. `archive/code/` is
git-ignored and absent from a fresh clone; it must be materialized from the live
site, which requires network access to `lettersfortitles.com`:

```sh
python3 tools/archive.py --tag "Rune Code" --variant full \
  --images-dir archive/code --manifest data/media-code.json --skip-pages
```

The key carrier, and the only acceptable evidence for this gate:

| Field | Required value |
|---|---|
| Local archive file | `2021_11_Loop.lettersfortitles-verntonkin.jpg` |
| Canonical URL | `https://lettersfortitles.com/wp-content/uploads/2021/11/Loop.lettersfortitles-verntonkin.jpg` |
| Dimensions | 2062 × 1528 |
| Bytes | 5,734,273 |
| SHA-256 | `33b777ed8f09bd0c3421d4b17c2f87bef8e878e77c8d75939e4dd2d58158874c` |

`2023_03_253-E-Letters-for-Titles-Vern-Tonkin.jpg` is a filename-run asset and
must never be used as the key carrier. See § 2 rule 2.

### 4.2 Three outcomes, and only three

**Outcome A — provenance-blocked.** The bytes cannot be fetched, or the fetched
file's dimensions, byte count, or SHA-256 do not match § 4.1.

- Do **not** attempt key transcription. Nothing has been learned about the key.
- Record a **provenance** finding, not a reading finding.
- Block v0.27 and route remediation to a v0.26.2-style provenance pass.
- The nine/seven partition is preserved as **untested**, not disproven.

This outcome exists so that a network failure and an evidentiary failure cannot
be recorded as the same thing.

**Outcome B — key confirmed.** All 29 cells, independently re-derived from the
authenticated 2062 × 1528 image, match the committed table in
`research/rune-code.md` cell for cell.

- The inherited nine-contested / seven-agreeing partition stands.
- Proceed to § 5.

**Outcome C — key mismatch.** The authenticated image is read successfully and
one or more of the 29 cells differs from the committed table.

- **Halt v0.27 adjudication.**
- Record a key discrepancy requiring an owner ruling.
- Mark **both** the nine-dispute set and the seven-agreement set **unsafe** — a
  changed key can move a reading that currently agrees just as easily as one
  that does not.
- Both partitions must be re-derived after the key is resolved. Do not continue
  to § 5 or § 6 on the old partition.

"Independently re-derived" means read from the image. A re-derivation that
consults either lineage's existing table before producing its own 29 cells does
not satisfy this gate.

## 7. *Octave* — a separate question, gated

*Octave* (`P261`) is **not** a tenth transcription dispute and must not be
folded into § 6. The nine are disputes in which both lineages read a plate and
disagree. *Octave* is prior to that: the seed registers a page URL, empty
`natural_dimensions` and `source_sha256`, and `not applicable` as the
`visual_fingerprint_type`; it holds **no image carrier at all**, while the
harvest holds
`Octave-Lettersfortitles-VernTonkin.jpg` (1083 × 981,
`89fa0ab057b1546554bccc02ced14139e61ab8580b30a6ce2e5f092732849109`) and reads an
inscription on it.

The question is therefore **classification**: does this carrier bear a Rune Code
inscription at all?

- **Gated on v0.26.2** registering the carrier (§ 1). Until that record exists,
  this question is not asked.
- Answering "yes" does **not** transcribe it. A transcription, if warranted,
  follows in a later bounded pass.
- Answering "no" is a complete and acceptable answer.
- The aggregate delta between the lineages — seed 17 (14 ordered + 1 rebus + 2
  key), harvest 16 message plates + 1 key — is entirely this carrier.

## 9. Stop rules

1. **No semantic completion from theme.** A reading is not preferred because it
   reads well, fits the poem, or completes a sentence grammatically. § 3a's
   withdrawal of the earlier *For Anybody* recommendation is the governing
   precedent: the seed's version is more complete and grammatical, and that was
   explicitly held to be suggestive rather than adjudicative.
2. **No silent lineage overwrite.** `LINEAGES.md` § Authority rule. A ruling
   records what was decided and why; it does not delete the losing record.
3. **No ruling from downscaled media when larger bytes exist.**
4. **No iterative one-plate Claude↔Codex loop.** One bounded comparative pass.
   The failure mode being avoided is a resumed plate-by-plate exchange.
5. **No in-place edit to `corpus-seed/`.** Any such edit invalidates the
   1,415-file `MANIFEST.sha256` and fails `tools/verify-corpus-seed.sh` in CI.
   Adjudication results arrive as a new release with a regenerated manifest.
6. **"Unresolved" is a valid outcome.** A carrier that cannot be settled on the
   available evidence is recorded as unresolved with its reason. Forcing nine
   rulings because there are nine carriers is itself a failure.
